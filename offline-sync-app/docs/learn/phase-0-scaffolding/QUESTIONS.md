# Phase 0 — Scaffolding: Questions

## L1 Beginner

**Q1. What is a router, and why does this app need chi?**
A router maps a method plus path (`GET /health`, `POST /api/sync`) to a handler function. Go's standard library can do this, but chi adds route groups and ready-made middleware. The app uses a group to put JWT verification on `/api/*` only. Source: [router.go](../../../internal/httpapi/router.go).

**Q2. Why does the repo run Postgres, Cognito, S3 and EventBridge in Docker?**
Developers need the same services as prod without an AWS account or a bill. Each has a stand-in: real `postgres:16`, `cognito-local`, `minio`, `moto-server`. Source: [docker-compose.yml](../../../docker-compose.yml).

Try it:
```
make compose-up
```

**Q3. What makes the web app a PWA?**
A manifest (name `FieldSync`, `display: 'standalone'`) plus a service worker, both generated by `vite-plugin-pwa`. That is what lets it install and load offline. Source: [web/vite.config.ts](../../../web/vite.config.ts).

## L2 Junior

**Q4. Trace `curl localhost:8080/health`.**
`http.ListenAndServe(cfg.Addr, router)` in [cmd/server/main.go](../../../cmd/server/main.go) receives it. chi runs the middleware chain (`RequestID`, `RealIP`, `Logger`, `Recoverer`, CORS), matches `GET /health`, and calls `healthHandler`, which encodes `{"status":"ok"}`. `/health` is mounted outside the `r.Group` that uses `verifier.Middleware`, so no token is needed. Source: [router.go](../../../internal/httpapi/router.go), [health.go](../../../internal/httpapi/health.go).

Try it:
```
make dev-server
curl localhost:8080/health
```

**Q5. How do settings reach the Go program?**
`make dev-server` runs `bash -c` with `set -a`, sources `.env` and `.env.local` if they exist, then `go run ./cmd/server`. `config.Load()` reads each variable through `getenv`, which falls back to a default when the variable is unset or empty. Source: [Makefile](../../../Makefile), [config.go](../../../internal/config/config.go).

**Q6. How does the same `.env.local` reach the React app?**
`vite.config.ts` sets `envDir` to the repo root. Vite exposes only variables prefixed `VITE_` to browser code (for example `VITE_API_URL` in `import.meta.env`). The Go server ignores the `VITE_` copies and reads the unprefixed ones. Source: [vite.config.ts](../../../web/vite.config.ts), [scripts/seed-cognito-local.sh](../../../scripts/seed-cognito-local.sh) (it writes both sets).

## L3 Mid

**Q7. Why one router for both `cmd/server` and `cmd/lambda`?**
So local dev and prod run the same handler code. `cmd/server` serves it with `http.ListenAndServe`; [cmd/lambda/main.go](../../../cmd/lambda/main.go) wraps the same `httpapi.NewRouter` with `httpadapter.NewV2`. The cost: `NewRouter` must accept dependencies that only one runtime really uses (the Lambda builds a `wsstub.NewHub()` whose `/ws` route is unreachable there, per the comment in that file).

**Q8. Why MinIO instead of LocalStack for S3?**
MILESTONES (Phase 3) says LocalStack's image refused to start without `LOCALSTACK_AUTH_TOKEN`. MinIO is free, needs no token, and speaks the S3 API, so the Go client only needed a custom endpoint and path-style addressing. Source: comment above `minio` in [docker-compose.yml](../../../docker-compose.yml), `storage.New` in [internal/storage/s3.go](../../../internal/storage/s3.go).

> Note: MILESTONES Phase 0 still lists LocalStack; the compose file does not.

**Q9. What tests cover Phase 0, and what do they prove?**
None are committed. `make test` (`go test ./...`) has no test for `/health`, the router, or config. The only evidence is the manual `curl` and `npm run build` checks recorded in MILESTONES. That proves it worked once on one machine, not that it stays working. Adding a `httptest` test for `healthHandler` and a table test for `getenv` would be cheap.

Try it:
```
make test
```

## L4 Senior

**Q10. What does `http.ListenAndServe` in `main` not give you?**
`main` calls the package-level `http.ListenAndServe`, which uses a server with no read, write, or idle timeouts, and there is no signal handling or `Shutdown`. A slow client can hold a connection open, and a deploy kills in-flight requests. Not solved in this repo. Source: [cmd/server/main.go](../../../cmd/server/main.go).

**Q11. What breaks if you run several `cmd/server` instances behind a load balancer?**
The WebSocket hub is an in-memory map inside one process, and the notifier loop is a goroutine sharing it. A push can only reach connections held by the same instance. The package comment in [internal/wsstub/hub.go](../../../internal/wsstub/hub.go) calls this a documented local-dev fidelity gap; prod uses API Gateway WebSocket plus the Management API instead. The local stack never exercises that path (MILESTONES says real WebSocket API GW is only exercised against real AWS later).

**Q12. What does `/health` fail to tell a load balancer?**
It always returns 200 and never touches Postgres, S3, or the JWKS endpoint. A server with a dead database still reports healthy. A readiness endpoint that pings the pool would fix it. Not implemented. Source: [health.go](../../../internal/httpapi/health.go).

**Q13. What are the limits of the local emulator stack?**
`cognito-local` has no SRP, so sign-in uses `USER_PASSWORD_AUTH`; the compose file pins `4.0.0` and notes an upstream bug that hardcodes port 9229 in returned URLs. MinIO is not S3, Moto's EventBridge is a supplement, and Terraform is only `validate`d here (`make tf-validate` never applies). Passing locally does not prove behavior on real AWS. Source: [docker-compose.yml](../../../docker-compose.yml), [Makefile](../../../Makefile).

Try it:
```
make tf-validate
```
