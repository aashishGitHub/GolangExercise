# FieldSync

Offline-first field damage assessment app — Go + AWS serverless backend, React (Vite) PWA frontend,
Terraform IaC, event-driven fan-out layer. Full architecture and PRD:
[`docs/study-the-basic-requirements-md-and-sleepy-lovelace.md`](docs/study-the-basic-requirements-md-and-sleepy-lovelace.md).
Build order and progress: [`MILESTONES.md`](MILESTONES.md).

## Prerequisites
- Go 1.26+
- Node 24+ / npm
- Docker (for the local-AWS emulator stack)
- Terraform 1.5+ (writes/validates infra; `apply` targets real AWS and is never run automatically)

## Local-AWS emulator stack
Fully free patchwork — no LocalStack paid tier required:

| Service need                          | Local stand-in                          |
|----------------------------------------|------------------------------------------|
| Aurora Postgres                        | real `postgres:16` (no RDS API layer)     |
| Cognito user pool                      | `cognito-local` (jagregory/cognito-local) |
| S3 (photo uploads)                     | **MinIO** — not LocalStack; LocalStack's image refuses to start at all without a `LOCALSTACK_AUTH_TOKEN` (confirmed directly while building Phase 3: exits with "License activation failed" even for S3, contrary to what its own free-tier docs implied). MinIO is free/open-source, no signup/token needed, same S3 API. |
| EventBridge                            | Moto server (port remapped to 5001 on the host — 5000 collides with macOS's AirPlay Receiver) |
| SQS + Lambda event-source trigger      | **not emulated** — `internal/consume` polls `domain_events` directly instead (each consumer's own binary, e.g. `cmd/photo-processor`), guarded by the same `processed_events` idempotency table a real SQS-triggered Lambda would use. Prod uses real SQS + the `*-lambda` entrypoints (`cmd/photo-processor-lambda` etc.) via `internal/sqsconsume`, with partial-batch-failure reporting. |
| DynamoDB (`ws_connections`)            | Postgres, in both local **and** prod — this app's connection-churn volume never approaches what would justify DynamoDB (see `migrations/000002_add_domain_events.up.sql`'s comment) |
| API Gateway WebSocket                  | `cmd/server`'s in-process `/ws` route + `internal/wsstub` hub — only works locally because the notifier consumer runs as a goroutine sharing that exact hub (see its package comment). Prod uses a real API Gateway WebSocket API (`modules/websocket`) + `cmd/ws-connect-lambda` for `$connect`/`$disconnect` + the Management API for pushes (`cmd/notifier-lambda`). |

```bash
cp .env.example .env                 # S3/MinIO settings (Cognito settings come from .env.local below)
make compose-up                      # postgres, cognito-local, minio, moto-server
make migrate                         # applies migrations/ to postgres
./scripts/seed-cognito-local.sh       # creates/reuses a user pool + app client -> .env.local
make dev-server                       # loads .env + .env.local -> http://localhost:8080/health, ws://localhost:8080/ws
make dev-web                          # cd web && npm run dev -> http://localhost:5173

# Phase 7 consumers (each its own process; notifier runs inside dev-server instead — see table above)
make dev-outbox-relay
make dev-photo-processor
make dev-dashboard-aggregator
```

Schema changes: edit `sqlc/queries.sql` or add a migration (`migrate create -ext sql -dir migrations -seq <name>`),
then `make sqlc-generate` to regenerate `internal/db`. `make test-integration` runs the sync-service
integration tests against a real Postgres (needs `compose-up` + `migrate` first).

`.env.local` (generated by the seed script, gitignored) is read by **both** the Go server and
Vite — `vite.config.ts` sets `envDir` to the repo root so one file covers both. Signup
confirmation codes are fixed to `123456` (`CODE` env var on the `cognito-local` service) so
local dev/testing doesn't need to read them out of container logs.

## Repo layout
```
cmd/server/                    chi-lith entrypoint (plain HTTP server); also runs the WS stub + notifier loop
cmd/lambda/                    aws-lambda-go-api-proxy adapter — same router as cmd/server, runs on Lambda
cmd/outbox-relay/               local dev: polling loop        | cmd/outbox-relay-lambda/  prod: EventBridge Scheduler
cmd/photo-processor/            local dev: polling loop        | cmd/photo-processor-lambda/  prod: SQS-triggered
cmd/dashboard-aggregator/       local dev: polling loop        | cmd/dashboard-aggregator-lambda/  prod: SQS-triggered
cmd/notifier-lambda/            prod only — pushes via the Management API (local dev: goroutine in cmd/server)
cmd/ws-connect-lambda/          prod only — real API GW WebSocket $connect/$disconnect
internal/httpapi/              chi router + handlers (sync, locations, sites, photos, whoami, ws)
internal/auth/                 Cognito JWT verification (header, and VerifyToken for the WS query-param case)
internal/sync/                 sync service — idempotent upsert, LWW, <=10-photos rule; TxRunner wraps it +
                                internal/events in one transaction
internal/events/                Publish — the transactional-outbox write (domain_events row, same tx as the upsert)
internal/outbox/                the relay: domain_events -> EventBridge (or Moto locally)
internal/consume/               local-dev consumer loop: polls domain_events, dedups via processed_events
internal/sqsconsume/            prod consumer loop: SQS record -> dedup -> handle, partial-batch-failure reporting
internal/photoprocessor/        geotag validation
internal/dashboardaggregator/   recomputes location_stats
internal/notifier/              pushes to ws_connections subscribers (Hub locally, Management API in prod)
internal/wsstub/                the local-only in-memory WebSocket hub
internal/db/                   sqlc-generated queries (DO NOT EDIT — see sqlc/)
internal/config/               env-driven config
migrations/                    golang-migrate SQL migrations
sqlc/                           sqlc.yaml + queries.sql (source of truth for internal/db)
web/src/db/                    Dexie schema (locations, siteAssessments, photos, outbox)
web/src/capture/                offline capture — no auth, no network
web/src/sync/                   sync engine — drains the outbox to POST /api/sync
web/src/auth/                   Amplify Auth panel
infra/terraform/                modules/{network,database,auth,storage,compute,api,secrets,waf,eventing,websocket}
                                + envs/local (written & validated via `make tf-validate`, never applied automatically)
scripts/loadtest/               local NFR measurement tool (see MILESTONES.md's Phase 6 numbers)
docs/                           PRD + architecture plan
```
